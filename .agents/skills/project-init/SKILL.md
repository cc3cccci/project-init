# 项目初始化

先把「做什么、不做什么、怎样算做完」写进仓库，等用户确认后再写功能代码。示例 1–5 是唯一模板。引用时说「按 project-init 示例 N」。

落到目标仓库时：保留示例的标题、表格列和句子结构；把「书架」换成这个项目的事实。不知道的格子写「待确认」，不要编产品决定。文档语言跟用户这次对话。

## 执行

1. 仓库根：用户给的路径优先；否则 `git rev-parse --show-toplevel`；都没有就用当前目录，并告诉用户你用的是哪一个。
2. 看这三份在不在：`AGENTS.md`（或 `Agents.md`）、`docs/方案.md`、`docs/验收.md`。已有的不覆盖、不重排。只补缺的。已有 `AGENTS.md` 时不动原文，只把示例 3 末尾的「方案与验收」块追加到文末，让它指向新写的方案和验收。
3. 还不知道「这一期做什么、明确不做什么」时，先问这一句，问完再写。不要把示例里的书架写进用户仓库，除非用户说「先按示例落一份」。
4. 缺的文件按对应示例写入。日期用当天。
5. 用示例 4 的说法停住。不写功能代码，不改业务文件，不部署，不新建云资源。三份文档默认不提交；运行环境不保留工作区时（例如云端一次性 Agent），把这三份提交到新分支，功能代码照样不写，并在示例 4 的回复里写明分支名。
6. 什么算确认：用户明确说「确认」「可以开工」「按这个做」才算。沉默、追问、改某一句都不算；改完要再问一次。确认后先把 `docs/方案.md` 的状态行改成「已确认 · 日期」，再按 `AGENTS.md` 开工。
7. 用户之后要做下一期：按示例 5，只追加。不重写已有方案和已有 `AGENTS.md`。

## 示例 1 · 方案

写入 `docs/方案.md`。

```markdown
# 书架（第一期方案）

- 状态：待确认。确认前不写功能代码。用户确认后把本行改成「状态：已确认 · 日期」
- 日期：2026-09-25
- 目的：本文件是这一期做什么的依据。怎样算做完见 docs/验收.md

## 已确认

- 只在本机记「想读 / 在读 / 读完」，不上传
- 书由用户自己加，没有推荐，没有账号

## 这一期做

- 三列：想读、在读、读完
- 每本只有书名和作者；点一下改状态

## 不做

- 评分、书评、封面、扫描 ISBN
- 登录、云同步、分享
- 改已经在用的「笔记」

## 怎么走

打开就是列表。底部「加一本」进入编辑，返回回到列表。

## 待确认

- 书名最长多少字
```

## 示例 2 · 验收

写入 `docs/验收.md`。编号从 A1 起。一条不符就是 Fail，并记下环境、步骤、实际结果。

```markdown
# 第一期验收

对照 docs/方案.md。一条不符即 Fail。Fail 写环境、步骤、实际结果。

| ID | 验收项 | Pass 标准 |
|----|--------|-----------|
| A1 | 空列表 | 没有书时只有一行「还没有书，点下面加一本」 |
| A2 | 添加 | 书名「百年孤独」、作者「加西亚·马尔克斯」保存后出现在「想读」 |
| A3 | 改状态 | 把这本书改成「在读」后，「想读」里没有它，「在读」里有 |
| A4 | 范围 | 页面上没有评分、登录、分享 |
| A5 | 离线 | 断开网络仍能加书、改状态 |

## 怎么跑

- 规则：`node scripts/test-shelf.js`。测试还没有时，这里写「待确认」，不要为了填空先写测试
- 界面：在这个项目真正运行的环境里走 A1–A5。别的技术栈的预览不算
```

## 示例 3 · AGENTS.md

写入仓库根 `AGENTS.md`。产品结论以 `docs/方案.md` 和 `docs/验收.md` 为准。仓库里别的模板流程与这三份冲突时，以这三份为准。

````markdown
# 开工说明

本文件只讲先读什么、文件放哪、默认别动什么、怎么验收。产品以 docs/方案.md、docs/验收.md 为准。

## 0. 冲突时先听谁

1. 用户当次说的话
2. 做什么、不做什么：docs/方案.md；怎样算做完：docs/验收.md。两份互相矛盾时停下来问，不自行取舍
3. 文件放哪、默认别动什么、怎么验：本文件
4. 仓库里其他模板、规则、流程文件排最后

## 1. 这是什么

| 项 | 值 |
|----|-----|
| 仓库 | 待确认 |
| 怎么打开 | 待确认 |
| 不许改的入口 | 已有的「笔记」 |

## 2. 文件放哪

- 规则放纯函数，例如 `src/shelf.js`；页面只拼界面
- 改规则先改 `scripts/test-shelf.js`，再改函数。测试文件还没有时，先在验收里写「待确认」

## 3. 默认不要

任务没点名就不要：

- 做方案「不做」里的那些事
- 给这一期加网络、账号、分享
- 顺手改「笔记」
- 提交密钥、本地私有配置

## 4. 登记

新的存储键或配置项先写进这张表，再写代码。

| 键 | 谁用 |
|----|------|
| `shelf:` | 书架。一本书一个键 |

## 5. 现在做到哪

代码写完改「代码」列；验收全部 Pass 后由跑验收的人改「真实环境签过」；可以发布时改「可发布」。只改这张表，不改别处。

| 块 | 代码 | 真实环境签过 | 可发布 |
|----|------|--------------|--------|
| 第一期 书架 | 未写 | 未做 | 未做 |

## 6. 怎么验

```bash
node scripts/test-shelf.js
```

再按 docs/验收.md 的 A1–A5 在真实环境里点一遍。命令还没有时，本节约只保留验收文件路径。
````

已有 `AGENTS.md` 时，不动原文，只把下面这块追加到文末：

```markdown
## 方案与验收

- 做什么、不做什么：docs/方案.md；怎样算做完：docs/验收.md。两份互相矛盾时停下来问
- 验收：按 docs/验收.md 的全部 A 编号在真实环境里点一遍
- 本文件与上面两份冲突时：产品范围听方案和验收，工程约定听本文件
```

## 示例 4 · 确认前停手

三份文件落盘后，只回复下面这段，然后结束。把路径和编号换成刚写的那些。

```markdown
方案和验收已写好，功能代码还没动。

请看这三处：

- docs/方案.md 的「不做」和「待确认」
- docs/验收.md 的 A1–A5
- AGENTS.md 的「默认不要」

要改哪一句直接说。确认之前不加功能，也不提交。
```

三份文档提交到了新分支时，最后一句换成「要改哪一句直接说。确认之前不加功能；三份文档在分支 `<分支名>` 上，功能代码没动」。

## 示例 5 · 下一期

用户确认第一期并要求做下一期时，新写 `docs/二期方案.md` 和 `docs/验收-二期.md`。第一期文件不动。`AGENTS.md` 只追加下面三块，不重写全文。验收编号换一组，第一期的 A 编号继续有效。

`docs/二期方案.md`：

```markdown
# 第二期方案：笔记

- 状态：待确认。确认前不写这一期的功能代码。用户确认后把本行改成「状态：已确认 · 日期」
- 日期：2026-09-25
- 第一期 docs/方案.md 不动

## 已确认

- 每本书可以加一条文字笔记

## 这一期做

- 纯文字，最多 200 字

## 不做

- 不改第一期的三列和状态
- 图片、导出、分享

## 待确认

- 空笔记要不要保存
```

`docs/验收-二期.md`：

```markdown
# 第二期验收

一条不符即 Fail。Fail 写环境、步骤、实际结果。第一期 A 编号仍然有效。

| ID | 验收项 | Pass 标准 |
|----|--------|-----------|
| B1 | 加笔记 | 「百年孤独」写上「开头在马孔多」，保存后再次打开还在 |
| B2 | 上限 | 第 201 个字进不去 |
| B3 | 范围 | 三列和「想读 / 在读 / 读完」跟第一期一样；没有图片和分享 |

## 怎么跑

- 规则：`node scripts/test-notes.js`。还没有就写「待确认」
- 界面：在真实环境里走 B1–B3，并抽一条第一期的 A2，确认旧的添加还在
```

追加到 `AGENTS.md` 文末：

```markdown
## 第二期追加

- 笔记规则只放 `src/notes.js`。页面不写字数判断
- 默认不要给笔记加图片或网络
- 改笔记规则先改 `scripts/test-notes.js`
- 验收：`node scripts/test-notes.js`，再走 docs/验收-二期.md 的 B1–B3

| 块 | 代码 | 真实环境签过 | 可发布 |
|----|------|--------------|--------|
| 第二期 笔记 | 未写 | 未做 | 未做 |
```
